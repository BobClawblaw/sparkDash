# Interface language foundation

This is the small foundation requested in [the maintainer decision on PR #194](https://github.com/MiaAI-Lab/sparkDash/pull/194#issuecomment-6201610389). Settings, including its embedded browser-alert controls, is the first translated page. Navigation, other pages, the separate Alerts dialog, access-token prompt and server diagnostics remain in English for later focused changes. This is not whole-application translation. The existing full integration in #194 remains a reference; this branch starts from official main and does not rebase that branch.

## One loader and English source

`src/i18n/index.ts` owns one i18next instance with react-i18next. The small `language` and `settings` catalogs are bundled eagerly, so switching has no asynchronous download or additional backend. `src/main.tsx` initializes it before mounting. English JSON under `src/locales/en/` is the authoritative source and fallback; `src/locales/zh-CN/` mirrors it by page or namespace. There are no inline English fallback defaults, ICU plugin, ICU messages or intl-messageformat.

Settings → Language applies immediately without Save. The choice is browser-local (`sparkdash-locale`), survives reload and updates `<html lang>`. Server settings and other users are unaffected. A supported stored preference wins over browser language; unsupported languages fall back to English. Simplified Chinese browser tags and the earlier `zh-Hans` preference map to `zh-CN`; Traditional Chinese remains unsupported. Storage failures still permit switching for the current page.

## Adding strings and pages

Use `const { t } = useTranslation("settings")` and static `t("dialog.save")` keys. Add the English entry first, then the Chinese translation; keep IDs, settings values and raw diagnostics independent of display text. Namespaces are catalog files, not a second loader. Add future namespace imports/resources to the single loader and its tests in the corresponding page PR.

Use i18next interpolation (`"Hello, {{name}}"`) and ordinary plural keys (`items_one` / `items_other` with a numeric `count`); do not use ICU brace expressions. React escapes rendered text. Store stable message reasons rather than translated strings when feedback must change with language. Keep static namespaces and keys; use distinct `t` aliases if a file uses multiple namespaces. Direct `i18n.t()` calls and dynamic translation keys are rejected by the foundation checker.

`npm test` runs `npm run i18n:check` and its checker regressions before the existing suites. The AST check discovers production TS/TSX translation calls and fails for missing English source keys/catalogs, orphan Chinese keys, interpolation mismatches, duplicate JSON keys, dynamic/ambiguous translation calls and inline fallback defaults. It checks wired keys, not untranslated text on pages outside this foundation. Runtime tests cover fallback, ordinary plurals/interpolation, preference detection, blocked storage, same-mounted Settings switching, pending settings changes, raw errors and unchanged save payloads.

## Dependencies and validation

Only two direct build dependencies are introduced, both exactly pinned with the lockfile:

| Package | Version | Published (UTC) |
| --- | --- | --- |
| i18next | 26.4.2 | 2026-09-03 19:31:13 |
| react-i18next | 17.0.15 | 2026-09-21 18:19:20 |

Both exceed the two-week requirement on 2026-10-16. Metadata comes from the primary npm registry ([i18next](https://registry.npmjs.org/i18next), [react-i18next](https://registry.npmjs.org/react-i18next)). The new transitive closure is @babel/runtime 7.29.7, html-parse-stringify 4.0.1 and use-sync-external-store 1.7.0, also older than two weeks. A scoped override holds @babel/runtime at 7.29.7 because the newer eligible-range release is too recent; unrelated dependencies are unchanged. None introduces ICU/intl-messageformat. See THIRD_PARTY_NOTICES.md for licensing.

Use a dependency-supported Node release such as 22.23.2. Run `npm ci`, `npm test` (server collectors require native Linux/POSIX tools), `npm run typecheck` and `npm run build`. For browser acceptance, open Settings at desktop and phone sizes, switch English → 简体中文 → English, reload, check keyboard/accessible labels and no horizontal overflow, and verify a pending setting survives a language switch and Save. Use synthetic data for writes; no live device action is needed. Browser testing and passing unit tests do not imply GPU/model acceptance or deployment.
